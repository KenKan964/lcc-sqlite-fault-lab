# Security and safe use

**Experimental software. Never run this against production or customer data.**

The CLI creates new synthetic SQLite databases in an output directory that must not already exist. Child processes are launched by Python's `subprocess.Popen` with `shell=False`; fault injection uses `kill()` only on the returned child handle. CLI plans cannot supply a custom database path, token, executable or PID to the test child; `lab.py` rejects unknown options.

All data generated by the demo is synthetic (`op-001`, integer amount). JSON traces contain local PIDs and paths: review before publishing actual run output. Do not commit generated database files or experiment traces.

An output directory supplied through `--out` should be an owned, empty location. The sandbox marker and random token are accidental-misuse safeguards, not a security boundary against malicious processes with the same user permissions.

Do not generalize the test oracle to real external effects, multiple processes not controlled by this laboratory, or unrelated databases. `HOLD_UNKNOWN` means do not blind-replay. See `TECHNICAL_SPEC.md` for limitations.

For private vulnerability reporting, contact the repository maintainer through the repository's private security advisory mechanism when enabled. Do not publish sensitive or customer data in issues.
